The web, without the paper trail.

Verity is a desktop browser built from scratch on Electron. Nothing is tracked by default, nothing is written to disk unless you ask for it, and every privacy switch is real — it changes what the network layer does, not just what the interface says.

    Limits of the automated runs

      Real captures

      Photographed from the running application

      Written by npm run capture into artifacts/ and copied here at build time. Two of them are the chrome strip; the third is the new tab page.

      There is deliberately no full-window screenshot. The page surface and the side panel are separate Chromium views, and on this desktop a window capture does not include their pixels — the project reports that as a limit rather than shipping a blank image as evidence. The panel is verified by view geometry, visibility and DOM content against a real window instead, and the drawing at the top of this page exists for the same reason.

      Verification

      Two suites, because they can prove different things

      CommandWhat it covers
      npm run smoke 39 headless checks: the rule engine, omnibox resolution, session isolation, request filtering against a local fixture server, cookie and header handling, HTTPS-only and its exceptions, tab lifecycle, the error interstitial, every panel's DOM driven through its own view, the mascot everywhere it belongs, the panel following a live theme change, and the profile argument refusing to be tricked out of its directory.
      npm run diagnose 5 checks against a real, visible, composited window: strip geometry, palette resolution, panel view placement, and findInPage with real match counts.
      npm run capture The screenshots above, for human review.
      npm run verify Both suites together.

      A check that cannot run is reported as a skip, never as a pass. findInPage returns nothing to a software-composited window that never composited, so the smoke suite skips it and the diagnose suite proves the same flow against a real window.

      Install

      Run it from source, or build a real installer

      Requires Node 20+ and a desktop session — the browser renders real Chromium.

      There is no published release yet, so there is nothing to download from here: the installer is built on your own machine by the command above. It is also not code-signed, so Windows will warn on first run, and it installs per user — it never needs administrator rights.

      The two facts
      
            
        
              
      • 
                The side panel is its own view, not an element of the chrome document. Chromium
                composites the chrome document under the page views and never rasterises chrome
                pixels in a region a view has covered, so a drawer drawn there stays blank. A view
                renders as reliably as a page does.
              
        • 
              
      • 
                A child view does not always resolve through BrowserWindow.fromWebContents.
                The IPC gateway resolves a sender by view identity and origin, so exactly two
                documents can drive a window: verity://chrome and verity://panel.
                A web page never gets a bridge at all.
              
        • 
            
      
          
      
        
      
        
      
          This page is built the same way the icon is: tools/build-site.js lifts the mascot
          from icons.js, the palette from chrome.css and the engine from
          blocklist.js, then reloads what it wrote and compares it against the app across
          72 probe cases. A rotted copy fails the build.
